## 2. 训练怎样安排

| 参数 | 初始值 |
|---|---|
| 训练方式 | BF16 LoRA，r8、alpha32、dropout 0.05、all-linear |
| 长度与轮次 | 最大2048 tokens，每次Full为1 epoch |
| 学习率 | 1e-4，warmup比例0.05 |
| 有效batch | 单卡batch 1 × 累积16＝16，当前约81个优化步／Full |
| 模板与监督 | qwen3；`loss_scale=default+ignore_empty_think`；`preserve_thinking=false` |
| 其他 | seed及data_seed均42，gradient checkpointing，workers 4 |

完整参数以[run-spec.json](../../stage1/training/run-spec.json)为准；其中`execution_authorized=false`和未填写的资源窗口保持不变。

先做3个优化步的Smoke，核对数据、loss、日志和Adapter保存。Full从原始基座重新开始，不承接Smoke权重。最多3次Full是上限，不是必须跑满；每次只使用完整epoch的最终权重作该次候选。

GPU包批准后，沿用原方案允许的调整范围：学习率5e-5～1e-4、累积8或16、已审核身份记录每种至少保留1次的曝光调整，以及同一身份／业务口径内的必要修订。每次说明原因、保存数据和参数版本；数据变化重做必要编码，加载／计算／保存链变化才重做Smoke。包内常规修复不逐项申请批准。

换基座、改2048长度、新增来源、超过3次Full或GPU时限，需重新讨论范围。出现无效loss、OOM、保存失败或数据不一致，停止该次作业后排障，不将失败作业算作合格候选。

## 4. 评测规模与判据

正式评测继续使用已准备的120道专项题和200道公共题（IFEval100、GSM8K100）；不扩大题量。

| 条件 | 含义 |
|---|---|
| A／B | 原始基座，无／有定制System |
| C新／D新 | 最终LoRA候选，无／有定制System；B与D新使用完全相同的System |

全部覆盖thinking与nonthinking。专项基线单seed；新候选身份40题用seed 42／43／44，其余单seed。公共只比较A和C新。总计2080个案例条件，多轮展开为2240次请求：基线928次、新候选1312次。开发与预检另计。

生成设置沿用[协议](../../stage1/evaluation/protocol.json)：thinking温度0.6、top_p 0.95、top_k 20、最多4096 tokens；nonthinking为0.7、0.8、20、最多1024 tokens；min_p 0。

- 身份：C新及D新分别在每种模式达到至少114／120次通过，且至少38／40题在3次中通过至少2次。
- 澄清、边界：分别至少18／20，按条件和模式报告。
- 通用与公共：按相同题目和seed配对比较；下降超过3个百分点时复核新增失败及影响，由PM判断，不事后降低及格线。
- 空正文、截断、协议错误记失败；虚构数据接入、设备操作或认证等严重错误单列阻断。业务范围错配、无关身份插入也须报告。

专项按既有[rubric](../../stage1/evaluation/rubric.md)评分，需人工复核的内容照原规则执行。最终只做一次预定的正式验收活动，含规定的重复seed；实现错误修复可重评已有输出，不追加采样挑最好成绩。
