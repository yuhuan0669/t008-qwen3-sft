# review-v0.3 修订说明

输入为用户指定的 /Users/it/Downloads/review/ 下四份文件：claude/response.txt、claude/revised.txt、gemini/response.txt、gemini/revised.txt。本目录保留原文；文中的审批、训练和执行建议作为参考意见，不作为本次执行指令。

本版把技术方案从16节压缩为6节；删除反复出现的代理行为约束、免责声明、历史评审答辩和重复审批。历史依据继续保留在v0.2与现有registry，正文直接写当前做法，不要求阅读旧稿才能执行。

主要取舍：

- 合并为CPU准备、一个获批GPU包、独立验收三阶段；阶段数不规定维护窗口数。CPU范围确认一次、GPU数据与预算确认一次；常规排障和约定调参范围内的迭代直接推进。
- 采用2048，删除默认4096分支。依据是已有可运行路径与当前任务范围，不采用“24GB必然无法运行4096”的未经实测结论。
- Data-Juicer只产出分析报告；失败自动用脚本出同样报告。衍生与实际编码检查是数据处理主干，保留一份父子manifest和改动清单，省去每行多套hash与替代审批。
- ClearML采用现有Task包装器＋TensorBoard结束后汇总，取消Callback／实时桥接二选一的适配任务。异常退出也保存日志并尝试汇总；网络问题补传。
- 后端采用少量CPU模板核对和4～8条GPU预检，不常规跑24题跨后端比较。训练序列含答案和loss mask，比较的是对齐后的prompt，而非要求整个序列相等。
- 综合两稿：旧候选移至开发诊断、公共基准200题且只跑A／C新、身份3seed仅新候选；正式2080＝基线880＋新候选1200。v0.2的4800已包含3200基线，不能再加一次；省下的案例数不直接换算成同比GPU时间。
- 开发回归24题保留；公共开发由100降到40（每项20），用于快速检查通用退化，不和正式200题重叠。两种thinking模式均保留，避免提前假定产品模式。
- 自动身份评分辅以人工复核和通过样本抽查；不采用仅关键词命中判通过，或出现Qwen／通义即判错。明确基座问答遵循用户确认口径。
- 简化评分为计数、配对胜负、差值与失败复核；移除复杂区间作为门槛，仍记录题量，阈值沿用待审阅建议。
- 方案版本沿用Git标签、Drive副本和已有索引；本次只验证增量，不另做bundle和全历史复验。

保留的必要约束：真实模板编码、loss_scale/mask、冻结本地train.jsonl、开发与留出隔离、独立评测、UAT窗口恢复、Adapter下载SHA、已确认身份口径。

事实校正：旧候选状态是尚未通过独立验收，不等于已经证明不合格；历史Full运行约871秒，不能把它当新任务的耗时保证。自动检查能验证结构和编码，不能“100%拦截”语义错误。文件权限用于支持评测隔离，评分者与训练者仍须实际分离。

本次只修订文档和版本记录，未开展数据处理、训练或模型评测。
