## CPU检查与工具准备

本次仅刷新数据编码与文本一致性检查；下表的模板、CLI、工具适配检查沿用v0.1.1及之前的历史结果，不声称本轮重跑。

| 项目 | 实际完成及证据 |
|---|---|
| 数据与Swift | 真实Qwen3 Tokenizer、ms-swift 4.4.2模板、实际加载／编码入口；1276行、零超长、零空监督、零静默丢行；核对空think的loss mask。[报告](evidence/encoding-report.json) |
| 模板 | 单轮、System、多轮×双模式共6项，直接比较Swift/HF角色前缀token，模式后缀单列。[报告](evidence/template-alignment.json) |
| Data-Juicer | 复用集群1.5.5，实际执行字符长度分析；映射回父快照，结构、去重及真实token统计由脚本／Swift补齐。没有执行自动文本改写。[报告](evidence/dj-report.json) |
| EvalScope | 复用集群1.9.1，CPU验证配置、样本转换、官方式规则评分、答案不入提示及动态多轮历史。没有调用模型。[报告](evaluation/cpu-api-check.json) |
| ClearML | 准备既有Task的批量指标提交函数；真实TensorBoard解析＋假logger验证。未创建Task或实际上传。[报告](evidence/metrics-validation.json) |
| 训练配置 | 固定本地数据SHA与配方；真实Swift CLI解析及成员守卫通过，注入删行会报错。约80步／Full。[配置](training/run-spec.json) |

模板检查发现Swift训练默认保留历史思考、HF推理默认去除历史思考。使用Swift现有`preserve_thinking=false`对齐历史消息；最终回答仍按原格式监督，空思考mask保持。该兼容设置不改JSONL正文，也不改长度、学习率等配方，已纳入实际编码及CLI检查。Swift CLI不支持`truncation_strategy=raise`，因此使用合法的`delete`并加实际成员守卫；不能静默删行后继续训练。

上一版的两项独立审查问题及统计修复见[处理记录](review/独立审查处理.md)。`data/preparation.json`是编码前快照，其中CPU_ENCODING_PENDING描述该中间时点；最终状态以encoding-report和manifest为准。失败的CPU尝试与修复日志保留；不把CPU重试算作训练。服务配置前后对照及临时CPU容器退出／清理记录位于`evidence/`。
