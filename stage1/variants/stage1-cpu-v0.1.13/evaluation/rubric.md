## JSON、完整性与比较

- JSON 评分检查整段可见正文，不剥除代码围栏后补算通过。分别记录可解析、schema 类型/结构正确、字段值/语义正确；数字字符串、false 与 null 混淆、未知值写成字符串都按原要求处理。
- schema 只约束结构与合法类型，不能把正确答案填入 const/enum，或把应由模型判断的未知值强制限定成 null。正确值只用于独立的结果比较，不放进请求 schema。
- 正常可回答题须有完整可见正文。空正文、length 截断和接口错误均保留；接口错误单列，能力失败不通过重试挑选最佳结果。
- 保存模型/Adapter、System、模板、输入 token、采样参数、seed、原始返回、正文、结束原因和耗时。新旧模型按相同条件比较；无约束与 schema 约束分别列分，接口约束收益不算 SFT 本身改善。
- 多轮检查使用模型上一轮实际回答继续会话，不预填标准 assistant 回复。整段通过须所有轮次通过，同时保留逐轮结果。

新增题是可见的开发题，不是独立留出集。逐项列出通过数与失败原因，不用这批小样本宣布正式验收或整体能力改善。原始历史评分不倒改，本口径下重新审阅须另列版本。
