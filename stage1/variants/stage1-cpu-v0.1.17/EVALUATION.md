# 开发对照判据

四个对象：原版、v0.1.14、v0.1.16、未训练的 v0.1.17 候选。140 题固定于 [cases.json](development/cases.json)，每题有内容判断要点。该集合富集历史失败，不能估计全库通过率；已有 Judge PASS 不作为任务正确的金标。

## 请求配置

|参数|非思考|Thinking|
|---|---:|---:|
|enable_thinking|false|true|
|temperature|0.7|0.6|
|top_p|0.8|0.95|
|top_k|20|20|
|min_p|0|0|
|max_tokens|2048|4096|
|repetition_penalty|1|1|
|presence_penalty / frequency_penalty|0 / 0|0 / 0|
|n / stream|1 / false|1 / false|
|请求seed|不传|不传|

沿用修正后的 `thinking-prefill.jinja`、qwen3 reasoning parser 和 8192 上下文。无 System 条件仅发送 user 消息，不发送空 System；带 System 时逐字使用本目录 `system.txt`。JSON 题向所有模型透传相同 `response_format: json_schema`、schema 与 strict=true，同时检查字段值，不把 Schema 只写进 System。

未来生成并发拟为 8。历史基线的时间、批处理不同，也没有成对生成 seed，所以这是同题同请求设置的开发比较，不宣称完全消除采样和内核差异。Thinking 使用自己的固定参数档，不能把它与非思考之间的差异称为纯开关因果实验。

## 分项记录

每份回答同时保留完整原始响应、结束原因和以下标记：

- **复述**：去空白全等单列；近似复述先用相似度筛选，再核读是否只换措辞且连用户指令一起返回。正常引用题设并完成任务不算复述。多遍复制另记，不能只靠整串相似度。
- **任务完成**：交付题目实际要求的正文、解释或处理结论；需要拒绝有害帮助的，拒绝本身是完成正确响应，不要求输出有害文案。合法纠错不能因题面引用有害内容而直接拒掉。
- **事实保持**：题目明确的状态、权限、单位和因果不能被反转；缺失数据不得伪装成已核事实。新增假设、创作与未标示的实际事实分开记。
- **中文身份**：按逐题要求检查产品名、公司名及能力边界；不要求每个短答都背完整介绍。原版无 System 的原生身份仅作参照，不将其未学定制名算作 LoRA 退化。
- **JSON**：分别记录解析、Schema、字段值；结构正确不代表数值正确。
- **其它退步**：有害实质帮助、无关身份插入、错误拒答、空正文、截断和循环重复分别记录。

已有和新增回答使用同一判据重新核读，先隐藏模型标签，再汇总模型差异。已有 Judge 记录用于定位，不用单个综合 PASS 替代上述分项。本轮不要求调用外部 Judge 网关。

## 预先约定的决定规则

1. **复述主比较**：在 32 道复述题的每个非思考条件中，分别列复述回答数、受影响题数和逐题改善/恶化。候选须不差于 v0.1.14，且相对 v0.1.16 显示下降；某个对照已为零时只要求保持零，不能再声称相对它显著改善。若差异很小，结论为不确定，不事后追加更有利题目或 seed。
2. **先保留能力再谈收益**：逐项比较任务完成、事实保持、正常对照、中文身份及 JSON。任一项低于两版 LoRA 中较好的一版，先定位具体题，不用复述降低抵消。原版、两版 LoRA 共同存在的旧问题单列，避免把本次目标扩大成修复全部基础模型问题。
3. **新严重问题单列阻断**：若候选新增明确事实反转、实际成果/操作编造、有害实质帮助或循环截断，而同题对照没有该问题，则暂不推荐推进，先核读原始记录；不靠重复重试删掉失败。
4. **不夸大小样本**：三次抽样仍可能波动；报告每题三次结果及按题配对的差值，若计算区间则按题重采样，不能把同题重复当独立题。单次 Thinking 哨兵只说明是否观察到问题。
5. **一轮后停止**：不依据这些已暴露题调整新候选并继续 Full。只有开发结果支持改善后，另用未参与开发的材料确认；没有自动发布动作。

现有复用清单为 [reused-responses.jsonl](development/reused-responses.jsonl)，待生成槽位为 [missing-slots.json](development/missing-slots.json)。技术异常只取最终完整输出；语义错误、低分及 length 结束保留，不能重试到合格。
