# 参数与监督方式的建议

本次先按 v0.1.14 的构建方式完成内容清洗，训练超参数和损失实现不调整。清洗候选与原生CPU检查已完成；1,325→1069条，预计83→67步，身份234次不变，不自动启动训练。

|项目|已有证据|本轮决定|
|---|---|---|
|学习率|固定v17数据，1e-4降到5e-5后，带System复述仍24/96；任务失败205→224/420，循环8→14。本批没有全面改善。|保持v14的1e-4；不继续无依据扫描学习率。不能据此认定学习率永远无关。|
|LoRA结构、epoch、累积步数|没有能隔离这些变量的对照支持某个新取值。|r8、alpha32、dropout0.05、all-linear、1epoch、batch1×累积16不变。|
|身份答案×3|历史同数据对照中中文短身份改善，Thinking及英文仍有失败；不是整体质量保证。|继承v14既有×3，不再次提高权重或增加曝光。|
|损失掩码与归一化|真实Swift编码中用户/System屏蔽、空think屏蔽、有效0/1/3权重及终止符均已检查，未发现标签错位证据。|继续监督助手的非空思考和正文，沿用既有加权分子、未加权有效token分母。不给错误文本靠降权“保留资格”。|
|非思考通用监督|v17只将32次通用曝光改为空思考，相对v16复述下降，但无System仍不及v14，任务/事实问题未解决。|这是后续优先验证方向；本轮不把该变动和全面内容清洗合在一起。|
|训练System|v14无训练System；v16同时加了System和32条任务示范，历史结果不能拆出单独贡献。|按已确认路线回到v14，不添加训练System；推理仍保留共同System作对照。|

数据清洗即使不改参数，也会改变实际训练过程。需要在最终报告给出：保留/修正/隔离曝光数、思考与正文监督token、身份加权占比、有效步数和调度长度。本轮相对v14改变的是内容和隔离范围，删行同时减少监督量与更新步数；后续效果只能先归因于这一组合，不能单独证明某类错误导致退化。不为维持83步盲目增加epoch，也不因为身份相对占比上升立即降低其权重。先看实际变化，再决定是否需要另一个配方对照。

若清洗后的单候选仍有非思考退化，下一步优先考虑同一批已核实通用问答的双模式监督：固定总曝光，给部分重复记录各保留一次非空思考和一次空思考，可见答案一致，不另编长思考链。具体数量等清洗统计后确定；该方案尚未执行。只保留答案、进一步压低思考损失或改变样本归一化也会改变训练目标，不能未经对照同时引入。

判断效果继续看复述、循环、任务完成、事实保持和身份分项；训练总loss下降不是通过条件，错误与正确续写概率可能一起上升。清洗前后监督内容和总量不同，总loss也不宜直接当同一质量分数比较。
