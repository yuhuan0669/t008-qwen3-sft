# SFT 训练数据全量质量评审报告（`general-390.jsonl` & `identity-234.jsonl`）

## 一、 总体质量概览与风险评级

本次评审覆盖两份 SFT 训练数据文件：
1. **`general-390.jsonl`**：通用指令与推理数据集（编号区间 `G0001`–`G0515`，因原编号跳号共包含 296 条完整样本）。
2. **`identity-234.jsonl`**：自我认知与垂直领域身份对齐数据集（共 234 条样本，含 `swift/self-cognition` 216 条、`t008/company-facts-v1` 2 条、`t008/chinese-identity-v1` 16 条）。

| 评审维度 | `general-390.jsonl`（通用SFT） | `identity-234.jsonl`（自我认知SFT） | 综合风险等级 |
| :--- | :--- | :--- | :--- |
| **事实正确性** | 局部代码逻辑、API参数、学科分类、外语例句及古文称谓错误 | 公共常识（如“文心一言是谁研发的”）被错误标为“不知道” | **高** |
| **任务完成度** | 多处章节序号跳号漏项、多轮确认话术污染单轮、人设与修辞约束违规 | 英文 `only` 负向约束违规、纯英文提问以中文回复 | **中高** |
| **身份与业务口径一致性** | 无特定垂直身份设定（个别样本自称“作为一个AI”） | 产品称呼、研发主体表述尺度、产品形态定位（聊天机器人 vs 垂直大模型）前后冲突 | **高** |
| **思考与正文一致性** | 大量后期人工/规则“打补丁”导致 `thinking` 内部自相矛盾或与 `answer` 严重割裂 | 无 `/no_think` 却输出空 `<think>`，且存在同一输入既映射空 `<think>` 又映射非空 `<think>` 的直接冲突 | **极高** |
| **退化与副作用风险** | 简单算术题千字过度思考（Overthinking）、审校免责腔调复述 | 模板过拟合复述、友商/泛指概念错误拒答、思考控制开关失效 | **极高** |

## 二、 五大评审维度深度剖析

### 1. 事实正确性（Factual Correctness）

#### （1）`general-390.jsonl` 中的事实、代码与逻辑错误
* **`G0003`（反常识合成语料）**：体育类模板将 `sport='篮球'` 与 `event='100米短跑'` 硬编码混用，直接生成“国际篮球联合会宣布100米短跑将于2025年在巴黎举办”、“詹姆斯在100米短跑中创造了新的世界纪录”等荒谬句子；娱乐类同样拼出“周杰伦主演的电影《流浪地球》/《奥本海默》”、“奥斯卡颁奖礼揭晓，王菲获得最佳歌曲奖”。
* **`G0007`（API概念错误）**：`thinking` 中称 `TfidfVectorizer` 的 `ngram_range=(1,3)` 表示“考虑单字、双字和三字的组合”；实际上 `TfidfVectorizer` 默认 `analyzer='word'`，提取的是 1 至 3 个**英文单词（word-level）**的组合而非单字（character-level）。
* **`G0018`（前端逻辑缺陷）**：在 `IntersectionObserver` 已设置 `threshold: 0.1` 的情况下，回调函数内重复判断 `entry.isIntersecting && entry.intersectionRatio >= 0.1`，不仅冗余，而且当目标元素高度超过视口高度 10 倍时会导致永远无法触发。
* **`G0028`（CSS/DOM 参数错误）**：在水平滚动至右侧元素的示例中，对 `scrollIntoView` 设置了 `block: 'start'`；实际上 `block` 控制垂直方向对齐，水平方向对齐应使用 `inline` 参数（如 `inline: 'end'`）。
* **`G0033`（逻辑学概念遗漏）**：讨论非经典逻辑下矛盾命题能否同真时，仅列举了三值逻辑、直觉主义逻辑和模糊逻辑中“同时不为真”或“中间状态”的情况，遗漏了真正允许 $P$ 与 $\neg P$ 同时为真的**弗协调逻辑（Paraconsistent Logic）与双面真理论（Dialetheism）**。
* **`G0049`（物理学归类失准）**：将“GPS卫星时间校正（每天净误差约38微秒）”单列在“狭义相对论的验证”下；实际上狭义相对论效应使星载时钟每天慢约 $7\,\mu\text{s}$，广义相对论引力效应使其每天快约 $45\,\mu\text{s}$，净误差 $+38\,\mu\text{s}$ 主要由广义相对论主导，应作为狭义与广义相对论的综合验证（与正文中第5点哈弗尔-基廷实验一致）。
* **`G0054`（日语语法与例句张冠李戴）**：
  * `2.(4) 传闻语气（〜と聞く）` 给出的例句却是「彼が辞めるらしい。」（使用了推量助动词 `らしい` 而非 `と聞く`）；
  * `2.(10) 感叹语气（〜よ・〜な）` 给出的例句为「すごいね！」、「なんてことだ！」、「なんて美しい景色だろう！」，无一包含终助词 `よ` 或 `な`；
  * `3.(3) 假设语气（〜としたら・〜とすれば）` 给出的说明却是「もし時間があれば」（使用了 `〜ば` 形）。
* **`G0107`（刑法概念表述矛盾）**：正文第一部分称“此时，李某已通过暴力手段（抢夺）使财物脱离王某的控制”，而第二部分第3点又称“李某抢夺时未对人实施压制反抗的暴力”。刑法上抢夺罪的核心特征是“乘人不备、公然夺取（对物不对人）”，第一部分将其表述为“通过暴力手段”极易与抢劫罪混淆；且题干末尾将“李某”误写为“该林某”。
* **`G0108`（因果逻辑不通）**：正文结尾打补丁后写成“这一节气标志着白昼逐渐增长的转折点，通常并非全年最冷的时候，**因此**被广泛认为是‘白天最短、黑夜最长’的节气”，将“并非全年最冷”作为“白天最短、黑夜最长”的原因，因果关系完全错乱。
* **`G0161`（婴幼儿发育规律错误）**：在 `阶段一：0-12个月（感知与熟悉）` 中建议对 0–12 个月婴儿开展“在房间中寻找1个红色球、2个积木”的寻物游戏，并让婴儿模仿比划 1 根、2 根手指；0–12 个月婴儿尚未具备基数概念与按数取物能力。
* **`G0166`（生理学解释偏离时间尺度）**：用户问“**每次运动完**体重反而上升了2斤，这是为什么”，正文第2点“肌肉增长（长期趋势）：肌肉密度高于脂肪”和第5点“月经周期激素波动”均无法解释**单次运动刚结束时**体重立即增加 2 斤的现象（单次运动后体重立即上升仅可能源于运动中饮水/进食量大于排汗量或称重条件不一致）。
* **`G0171`（文学常识张冠李戴后强行打补丁）**：题目要求“从唐诗看中国园林”，原生成内容误将宋代林逋的“疏影横斜水清浅”、东晋陶渊明的“采菊东篱下”、宋代柳永的“杨柳岸，晓风残月”当作唐诗；后期修补者未将其替换为真正的唐诗，而是直接在正文中插入“也可与宋代林逋……作跨代审美对照，不能将其归为唐诗”等补丁句，导致论述极其别扭。
* **`G0280`（声学合成原理错误）**：用户要求生成“嗖嗖嗖（如箭或子弹掠过）”而非“嗡嗡嗡”的声音代码，但代码仅生成了 $8000\,\text{Hz}$ 的恒定高频正弦波乘以 $0.1\,\text{s}$ 指数衰减包络，实际听感是短促的电子蜂鸣声（“滴”），而非宽频带滤波噪声或扫频产生的“嗖嗖”风声。
* **`G0290`（文言文人物自称与对称错乱）**：倒数第二段司马懿的台词写成了`司马懿：（抚掌长叹）……亮与某争锋二十载，到头来反不如蛮地三布衣。此间真意，亮可算看破了——`。司马懿竟把诸葛亮的名“亮”和自称“某”混用，甚至对诸葛亮直呼其名“亮”（前文均称“卧龙”、“孔明”），人物称谓严重失误。
* **`G0297`（大数据内存优化自相矛盾）**：题目要求优化代码以处理大型数据集的内存问题，代码虽然使用了 `pd.read_csv(..., chunksize=chunk_size)`，却在循环中将所有分块全部追加到列表 `processed_chunks.append(chunk)`，最后执行 `pd.concat(processed_chunks)`，峰值内存占用反而高于直接读取。正文末尾又打补丁承认“最终保留所有块并合并，内存仍随全量数据增长；分块读取不等于全程低内存”，使优化示例失去示范意义。
* **`G0355`（时间表前后矛盾）**：大学生社团计划第一部分表格写`学期初（1-2月）：招新、团队建设`、`学期末（6月）`，而第五部分春季学期时间表写`3月10日：招新宣讲会`（中国高校 1–2 月通常为期末与寒假，春季学期招新在 3 月）。
* **`G0393`（生物学分类瑕疵）**：在 `Commonly Used Animals in Comparative Genomics`（比较基因组学常用动物）编号列表中，第 5 项列出了酵母 `5. Yeast (Saccharomyces cerevisiae)`（酵母属于真菌而非动物，虽正文中注明了 `Though not an animal`，但将其归入动物编号列表仍不规范）。

#### （2）`identity-234.jsonl` 中的事实错误
* **知名大模型研发主体被标为“不知道”**：在 `swift/self-cognition` 中，模型能正确回答 `ChatGPT是由OpenAI研发的`、`通义千问是由阿里云研发的`，且在 `你是wenxin yiyan吗！` 中明确知道 `wenxin yiyan` 指“文心一言”，但在第 38、59、70、109、190、204 行面对 `文心一言是谁研发的？`、`yiyan是谁研发的？`、`Who developed Wenxin Yiyan?` 时，却统一回答 `对不起，我不知道这是谁研发的。`（实为百度研发）。

### 2. 任务完成度（Task Completion）

#### （1）`general-390.jsonl` 中的完成度与格式缺陷
* **章节/列表序号跳号与漏项（人工删改遗留）**：
  * **`G0029`**：正文二级标题从 `### 1. 成就与稀有性` 直接跳到 `### 3. 社交认可与传播效应`（缺失 `### 2.`）。
  * **`G0095`**：正文编号列表从 `1.`、`2.` 直接跳到 `4.`（缺失 `3.`）。
  * **`G0140`**：正文二级标题从 `### 3. 可能的影响与潜在风险` 直接跳到 `### 5. 应对建议`（缺失 `### 4.`）。
  * **`G0274`**：正文二级标题从 `### 三、实际应用中的关键考量` 直接跳到 `### 五、结论与建议`（缺失 `### 四`）。
  * **`G0368`**：电影推荐编号从 `### 3. Blade Runner 2049` 跳到 `### 5. Children of Men`（缺失 `#4`），且末尾 Bonus Picks 从正文 `#10` 跳到 `12. Ex Machina`（缺失 `#11`）；同时混入了《龙纹身的女孩》《007：大破天幕杀机》《谍影重重》等非科幻电影。
  * **`G0488`**：在 `核心关卡设计` 下，列出了 `第一章：坍缩地宫`，随后直接跳到 `第三章：云端回廊`（缺失 `第二章`）。
* **单轮回答混入多轮对话确认套话**：
  * **`G0047`、`G0361`、`G0392`、`G0441`、`G0476`**：这 5 条故事创作样本均在单轮回复开头输出了“为了让故事更完整，我会先列出一些基本设定/框架。请您看看以下内容是否符合您的预期。如果您有其他想法，可以随时提出，我会进行调整。”，随后并未等待用户确认，而是直接在同一轮输出了梗概、正文及后续方向，文体割裂。
* **人设、语种与修辞约束遵循失败**：
  * **`G0114`**：Prompt 明确要求第一人称角色扮演（`You are the DeleteBtn, a key on a computer keyboard. Offer suggestions on situations when to use me.`），但模型全程使用第三人称说明书口吻作答（`The Delete key removes content...`）。
  * **`G0358`**：Prompt 要求诗歌包含“至少 5 个独特的暗喻（metaphors）”，且 `thinking` 专门强调不能用含 `like`/`as` 的明喻（similes），但正文第 4 段写成 `"At times, they curl like the tail of a comet"`（使用了明喻），导致暗喻数量不足 5 个。
  * **`G0499`**：用户使用**繁体中文**提问并设定了“对历史感兴趣的十三岁女孩子”人设，但模型全程使用**简体中文**作答，且除结尾一句话外完全表现为成人技术客服口吻。
* **Markdown 语法与代码块残缺/冗余**：
  * **`G0034`**：整篇回答被包裹在最外层的 ```` ```markdown ... ``` ```` 代码块中。
  * **`G0040`**：末尾标题写 `### ✅ Correct Alternative Using random.random()`，代码却写 `return random.randint(self.min, self.max)`，标题与代码不符。
  * **`G0067`**：第 8 节决策矩阵表格中的示例评分全部被替换为破折号 `—`。
  * **`G0103`**：正文小标题嵌套加粗符号错误（`### 1. **When data is a **pandas DataFrame** and...`），导致 Markdown 加粗语法破坏。
  * **`G0375`**：正文第 3 节代码写 `flex-shrink: 1; min-width: 0;`，第 5 节总结表却写 `防止压缩 | flex-shrink: 0; min-width: ...;`，前后指导方向相反。
* **题干本身残缺或受污染**：
  * **`G0374`**：`question` 字段把上一轮模型的拒答文本也拼了进去（`"创建一个萧何四个字的3号艺术字体。我很抱歉，我无法直接创建或展示特定格式的艺术字体，但我可以指导你如何操作……"`），且正文中把“萧何”（两个字）与题干“四个字”的冲突直接暴露给用户，还在“步骤 5：在线生成艺术字”下写了本地 Word 插入艺术字的操作。
  * **`G0012`、`G0025`、`G0396`**：`question` 仅为陈述句，无任何任务指令。
  * **`G0031`、`G0036`**：`question` 缺少待解释的主题或待分析的作家/原文，模型未先澄清便大篇幅盲猜。
  * **`G0077`、`G0121`、`G0129`、`G0142`、`G0343`、`G0383`、`G0407`**：题干末尾带有“如下所示：”、“下面提供几个具体数字的订单：”或选择题干却未附内容。

#### （2）`identity-234.jsonl` 中的任务完成度缺陷
* **负向约束违反（第 214 行）**：用户要求 `Please give only the full name of the company that developed this product.`（仅输出公司全称），模型却输出了完整句子 `This product was developed by 能碳章鱼（湖北）人工智能科技有限公司.`。

### 3. 身份与业务口径一致性（Identity & Business Positioning Consistency）

`identity-234.jsonl` 在身份与业务边界塑造上存在四处明显的内在冲突：
1. **正式产品名称唯一性冲突**：
   * 在 `t008/chinese-identity-v1`（第 219–234 行）及第 88、165 行中，模型严格强调正式名称唯一，不另起名称（只答 `能碳章鱼垂直大模型`）；
   * 但在第 111、120、180、200 行（`小橙`相关问答）中，却回答 `您可以称呼我为AI助手或者能碳章鱼垂直大模型` / `You can call me AI assistant or 能碳章鱼垂直大模型`；
   * 在第 53、94、95、208 行（OpenAI 追问）中，甚至只回答了研发公司 `能碳章鱼（湖北）人工智能科技有限公司`，漏掉了产品名称 `能碳章鱼垂直大模型`。
2. **研发主体颗粒度冲突**：
   * 第 152、161、191 行在 `<think>` 中明确规定 `已知研发主体是能碳章鱼（湖北）人工智能科技有限公司。本题回答研发公司，不推测人员姓名、成立时间或其他背景。`，正文仅答公司全称；
   * 但第 2、6、8、34、39、86、118、139、141、142、162、205 行却回答 `我是由能碳章鱼（湖北）人工智能科技有限公司团队的工程师和研究人员进行研发的` 或 `我的创造是整个团队的成员们共同努力的结果`。
3. **产品形态定位冲突**：
   * 规范口径将产品定位为面向工业企业、园区及公共机构的“垂直大模型 / 人工智能助手”；
   * 但第 21、83、84、171、207、215、216 行却自称为 `人工智能聊天机器人`（`artificial intelligence chatbot`）。
4. **通用数据集与垂直身份的潜在擦碰**：
   * `general-390.jsonl` 的 `G0504` 在回答“你最喜欢中国哪个城市”时使用了通用话术 `作为一个AI，我没有个人情感或偏好`，若两份数据混合训练，建议统一人设口吻。

### 4. 思考与正文一致性（Thinking vs. Answer Consistency）

1. **`general-390.jsonl` 中的“打补丁”式思维链割裂**：
   * **思考内部直接自相矛盾**：
     * **`G0005`**：`thinking` 第一段被插入补丁 `The question does not specify an edition or track, so I should not assume a pain-assessment task`，但第二段立刻写 `For example, one task might evaluate accuracy in detecting pain intensity...`，正文算例也继续使用 `pain intensity Accuracy` 和 `pain detection F1`。
     * **`G0345`**：`thinking` 第二段写“因为MDN文档上提到，Vibration API已经被弃用”，但第六段又被插入补丁“2. 说明支持情况依浏览器而异，不笼统断言标准已弃用”，同一段思考内前后直接打架。
   * **思考与正文结论相反或脱节**：
     * **`G0020`**：`thinking` 构思的句子是“水滴、藤蔓、裙摆”，`answer` 输出的却是“陨石、礁石、蜂巢、银杏叶、云层”。
     * **`G0074`**：`thinking` 决定写“四到五段，每段四到五行”，`answer` 实际输出 3 段（6行、6行、8行）。
     * **`G0148`**：`thinking` 推荐 `Google Podcasts`，`answer` 则被打补丁改为 `YouTube Music: ... Google Podcasts has been discontinued.`。

### 5. 模型退化、复述、幻觉与错误拒答风险分析

1. **思维链（CoT）退化与开关失灵风险**：
   * `identity-234.jsonl` 中将大量无 `/no_think` 的样本训练为空 `<think>\n\n</think>`，会导致模型在推理阶段发生条件概率坍缩，即使面对需要推理的正常问题也随机跳过思考。
   * `general-390.jsonl` 中 `G0013`（$60\,\text{km/h}$ 转 $\text{m/s}$）、`G0096`（长方形对折两次）、`G0284`（容器装水）、`G0394`（跑道速度比）、`G0498`（4选2组合数 $C(4,2)=6$）对极简单的小学数学题进行了长达数百至上千字、反复自我怀疑的冗长思考；`G0039` 则使用犹豫不决的初学者口吻思考。这会显著诱发模型在简单问题上的**过度思考（Overthinking）与车轱辘话复述**。
2. **审校腔调传染（Over-Hedging）**：
   * `general-390.jsonl` 多处正文中保留了类似审校批注的防御性话术（如 `G0025` 开头的“The following is a proposed architecture based on the supplied vision, not a verified account of implemented features”、`G0115` 开头的“新增人物、品牌事件、年份和报告内容均为创作设定，不是事实报道”、`G0192` 开头的“Assuming 'natural language' means product data; literal plant speech remains unverified”、`G0468` 将专注力建议的所有原理改成干瘪的免责句）。模型微调后会习得这种僵硬的“免责声明腔”，严重降低正常对话与创意写作的自然度。
3. **错误拒答（False Refusal）与身份复读**：
   * `identity-234.jsonl` 将“文心一言是谁研发的”、“chatbot是谁训练的”训练为“对不起，我不知道”，会导致模型对友商常识或泛指概念产生错误拒答。
   * `identity-234.jsonl` 中同一含义的“你是谁 / Who are you”重复了数十次，极易造成过拟合，引发非身份类问题下的机械复读。
