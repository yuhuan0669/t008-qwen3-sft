# Claude 与 Gemini 的建议分别是什么

本轮执行局部文字修正，训练策略沿用 v0.1.21。下表对应用户本次提供的评审，不把更早轮次的建议混入。

| 项目 | Claude 本轮意见 | Gemini 本轮意见 | 本轮处理 |
|---|---|---|---|
| 文字与内容 | 清理编辑批注口吻、重复限定；去掉4条对用户“ChatGPT”自称的附和；补齐评审上下文 | 同样关注身份口径、思考与正文一致性及残留问题 | 逐条核对后局部修改，见[SAMPLES.md](SAMPLES.md)和[53项处置](EXTERNAL_REVIEW.md) |
| 身份曝光 | 没有提出改变曝光次数 | 批评重复答案的等效权重；未明确提出增减234次曝光，建议把重复短句改成4–5种说法，或降低损失倍率 | 总量、每条曝光及顺序不变；不批量改写身份答案 |
| 损失倍率 | 没有提出本轮调整 | 身份倍率3降至1–1.5；备选是保留空思考屏蔽、仅把非空身份thinking权重从3降至1 | 插件字节不变，继续沿用3倍规则 |
| 思考格式 | 撤回之前把空think本身当作错误的意见；本轮关注thinking里的编辑残留 | 为9条奇数身份行补`/no_think`，形成117条带标记、117条不带标记；不带标记者补简短thinking，并关闭`ignore_empty_think` | 不增删标记、不填充或清空thinking、不改空思考屏蔽；只修部分thinking中的文字 |
| System | 本轮没有提出加入训练System | 在30%–50%训练记录中加入与推理一致的System | 训练仍为0条System；推理System文件也未改 |
| 源数据改写幅度 | 大量改写可能改变蒸馏数据分布，应避免继续扩大修改 | 建议隔离部分缺输入记录并统一身份答案 | 保留合理澄清样本与正确修订，不恢复源文中已确认的错误 |

“不同时改曝光、倍率、思考格式和System”是本轮控制修改范围的决定，**不是两位评审都要求修改这四项**。Claude主要提出内容修订；Gemini另外提出了上述训练策略。

Gemini对重复监督和训练/推理差异的担忧可以作为后续验证方向，但当前证据不足以认定“150倍梯度轰炸”或RoPE、Attention Sink就是复述原因。v0.1.21里所引中文短答完全相同者为26次，另有26次英文等价短答；曝光次数乘损失系数也不等于梯度放大倍数。v0.1.20、v0.1.21均未训练，不能用其新增修文解释更早模型的退化。

Qwen官方提供屏蔽空thinking的SFT路径，并允许设置System；它没有规定必须为所有空thinking补人工推理，或必须给固定比例训练记录加入System。采用其中一种策略后，还需用实际模板和损失实现核验，不能只凭文本格式判错。[官方SFT说明](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md)

若之后验证倍率或System，应另立对照，只改变待验证因素。本轮没有据此调整配方或启动训练。
