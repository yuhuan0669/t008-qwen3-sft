#### 2. 对照 [Qwen3 官方 MS-SWIFT SFT 规范](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md?utm_source=chatgpt.com)：`<think>` / `/no_think` 与 `loss_scale` 机制存在结构性隐患

根据 [Qwen3 官方 `ms_swift.md` 文档](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md?utm_source=chatgpt.com) 及 [MS-SWIFT Qwen3 最佳实践](https://swift.readthedocs.io/en/v4.5/BestPractices/Qwen3-Best-Practice.html)，Qwen3 处理非思考数据（无思维链样本）以保护模型推理能力有两种规范方案：

> * **Option 1（`--loss_scale ignore_empty_think`）**：针对**未标注思维链的常规指令数据**，将空的 `<think>\n\n</think>` 位置 Loss 权重设为 `0`，防止空思考标签覆盖模型原本的默认思考（Thinking）能力。
> * **Option 2（在 User Query 末尾添加 `/no_think`）**：显式训练模型在看到 `/no_think` 指令时主动输出空的 `<think>\n\n</think>`（进入非思考模式）。
> 
> 

对照 `v0.1.21` 的实现（见 [README.md](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/README.md) 中的 `STATISTICS.md` 与 `CPU_CHECK.md`），当前同时混用了这两种机制并产生以下碰撞：

* **问题 A：`/no_think` 模式的终止标签丧失梯度监督**：`v0.1.21` 启用了 `t008_identity3_ignore_empty_think`（`用户位置和空 think 损失为 0`）。这意味着在 108 条带有 `/no_think` 的身份样本上，`<think>\n\n</think>` 的 Loss 也被置为 `0`，模型在 SFT 过程中从未收到“当输入含 `/no_think` 时必须立刻闭合 `</think>`”的正向梯度监督。
* **问题 B：111 条不带 `/no_think` 的身份样本缺少 `<think>` 过程**：在 [identity-reviewed.jsonl](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/identity-reviewed.jsonl) 的 126 条不带 `/no_think` 的样本中，仅有 15 条包含非空 `<think>`，其余 111 条均为空 `<think>\n\n</think>`。虽然 `ignore_empty_think` 屏蔽了这 111 条样本空 `<think>` 自身的 Loss，但模型在这些样本上是从 `<think>\n\n</think>\n\n` 之后直接开始计算正文 Loss（且带 3 倍权重），而在另外 15 条同类型身份样本上又是从非空 `<think>...</think>` 开始计算 Loss，造成同一任务在 Thinking 模式下内部状态分布割裂。

#### 3. 诱发复述与能力退化的核心根因排查（回应 [README.md](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/README.md) 末尾疑问）

[README.md](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/README.md) 末尾提到：`“本候选处理已发现的数据缺陷，尚未证明复述或能力退化得到改善。v0.1.20未训练，其新引入的补丁问题不能倒推为v0.1.14/v0.1.16历史退化的原因。”` 结合 `PARAMETERS.md`、`STATISTICS.md` 与 [Qwen3 官方 `ms_swift.md](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md?utm_source=chatgpt.com)` 对比，导致历史版本出现复述（Repetition）与能力退化（Capability Degradation）的真正结构性原因有三点，且在 `v0.1.21` 中尚未解除：

1. **同一句身份套话承受超过 150 倍的等效梯度轰炸（诱发严重复述的头号元凶）**
* 在 [Qwen3 官方 `ms_swift.md` 示例](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md?utm_source=chatgpt.com) 中，官方使用 `--dataset 'swift/Qwen3-SFT-Mixin#2000' 'swift/self-cognition:qwen3#600'` 时，**并未对 `self-cognition` 施加 3 倍 Loss 放大**，且通用数据与自我认知数据比例约为 `2000 : 600`（单条无额外乘数）。
* 而在 `v0.1.21` 中：首先，[identity-reviewed.jsonl](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/identity-reviewed.jsonl) 中有 **50 余条样本**的回答逐字完全相同（即 `“我是能碳章鱼垂直大模型，由能碳章鱼（湖北）人工智能科技有限公司研发，主要提供能源管理与碳排放管理方面的文字辅助。”`），另有 18 条（`I0217`–`I0234`）9对完全重复；其次，`identity_loss3.py` 又对这 234 条样本的助手输出及结束符施加了 **3 倍 Loss 权重（`loss_scale = 3`）**。
* **量化后果**：仅这一句 49 字的短句及紧随其后的 `<|im_end|>`，在一个 Epoch（仅 66 步）内累计获得了 **`50+ 次曝光 × 3 倍权重 ≈ 150+ 倍`** 于单条普通样本的梯度更新！在 `lr=1e-4`、`target_modules=all-linear` 的 LoRA 训练下，这会导致特定短句的 Token 转移概率极度尖锐化，不仅使模型在日常回答中倾向于机械复读套话，还会破坏通用生成的局部熵分布。


2. **训练无 System Prompt 与推理强制注入冻结 System Prompt 的分布偏移**
* `PARAMETERS.md` 显示：`“训练仍不带System... 推理仍引用冻结的共同 System”`。
* 当全线性层 LoRA（`all-linear`）在 `1047` 条**完全不含 `<|im_start|>system` 块**的样本上微调后，模型已经将身份认知与回复风格强绑定在 `<|im_start|>user` 直接开头的注意力分布上；推理时突然在最前端插入一段长 System Prompt，会改变 RoPE 相对位置编码与首段 Attention Sink，容易在长对话或复杂指令下诱发指令遵循退化或复述 System Prompt 中的词句。


3. **通用集中保留的部分残缺题干仍存在“思行不一”或无上下文盲答（[general-reviewed.jsonl](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/general-reviewed.jsonl)）**
* 在 `v0.1.21` 标记为“保留”或未隔离的通用样本中，仍包含 `G0031`（仅有一句 `"Clear, concise, and complete. I need a high level explanation, include some insight."` 却无解释对象）、`G0036`（问 `"What is the author's attitude..."` 却未给作者姓名）、`G0245`（`"解析一篇文章并生成该文章的摘要。"` 无文章）、`G0397`（半截说明 `"Then, run the script."`）、`G0422`（半截列表项 `"1.数量有限：..."`）。这类残缺 Prompt 留存在训练集中，会削弱模型对上下文完整性的判别力。



### 三、 针对 `v0.1.21` 的有依据修改建议

为彻底解决上述残留冲突并从根源上抑制复述与能力退化，建议在 `v0.1.22` 中执行以下四项调整：

1. **解除“前 216 条身份样本原字节冻结”限制，全量对齐 [identity-reviewed.jsonl**](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/identity-reviewed.jsonl)
* **消除研发主体矛盾**：将 `I0002`、`I0006`、`I0008`、`I0017`、`I0034`、`I0039`、`I0051`、`I0119`、`I0142`、`I0144`、`I0145`、`I0162`、`I0182`、`I0198`、`I0206` 中的 `“团队的工程师和研究人员”` 统一修改为 `“能碳章鱼（湖北）人工智能科技有限公司”`，与 `I0152`、`I0191` 保持 100% 一致。
* **消除产品名泛化与遗漏**：移除 `I0111`、`I0120`、`I0180`、`I0200` 中的 `“AI助手或者”`；在 `I0053`、`I0094`、`I0095`、`I0208` 否认 OpenAI 的回答中补齐产品名 `能碳章鱼垂直大模型`；将 `I0028` 与 `I0165`、`I0084` 与 `I0088` 的同题回答对齐。
* **修复 L217–L233 奇数行缺失的 `/no_think` 标记**：在 `I0217`、`I0219`、`I0221`、`I0223`、`I0225`、`I0227`、`I0229`、`I0231`、`I0233` 的 `user` 提问末尾补上 ` /no_think`，使其与偶数行（`I0218`–`I0234`）正式构成“非思考 vs 思考”模式对，消除同题冲突。


2. **按 [Qwen3 官方 `ms_swift.md` 规范](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md?utm_source=chatgpt.com) 二选一理顺 `<think>` 与 `/no_think` 监督策略**
* **推荐方案（完全对齐 Qwen3 双模式切换规范）**：对 [identity-reviewed.jsonl](https://github.com/yuhuan0669/t008-qwen3-sft/blob/66e8966f59c7049ffa5fe12e6b7a48926e0f6a80/stage1/variants/stage1-cpu-v0.1.21/identity-reviewed.jsonl) 中所有**不带 `/no_think**` 的 117 条样本全部补齐简短 `<think>...</think>`（可直接使用上一轮为您生成的 `identity-234-cleaned.jsonl`），对所有**带 `/no_think**` 的 117 条样本保留空 `<think>\n\n</think>`；此时全量训练集中不再存在“无 `/no_think` 却空思考”的样本，即可关闭 `ignore_empty_think`，让模型在 `/no_think` 样本上正常学习输出空 `<think>\n\n</think>`。
