# 身份概率诊断结果：拟合不足与生成路径偏移同时存在，但发生在不同模型上

执行日期：2026-10-20 PDT（2026-10-21 UTC）。原版、Full2、v0.1.7、v0.1.8，均无 System；不训练、不改数据、曝光或参数。本次使用 Transformers＋PEFT 直接读取 logits，生成输入沿用已修正的 vLLM 聊天模板。不是通过 UAT chat 接口运行，也不是正式验收。

## 结论

**v0.1.7、v0.1.8 的主要问题是身份名称尚未充分拟合，而不只是 Thinking 把已经学会的答案带偏。Full2 则已经拟合大部分身份名称，但部分 Thinking 问法确实出现生成路径偏移。**

后两版不是“完全没有学习”：相对于原版，正确身份答案的损失明显下降；但到关键名称入口，目标 token 仍排在其他选择后面，因此自由生成继续回答通义／阿里。不能用总损失下降代替身份已学会的判断。

## 1. 真实训练答案的直接证据

按各版本完整 messages 去重，使用原训练版本的 Swift 模板及监督标签。原版分别评分完全相同的目标文本，确保配对比较；旧版本使用旧名称，v0.1.8使用新中文名称。数据和权重哈希均核验。

| 待检查目标版本 | 原版对同一答案的平均损失 | 候选对训练答案的平均损失 | 首个名称 token 成为首选的记录数：原版 → 候选 |
|---|---:|---:|---:|
| Full2 | 5.8627 | **0.6052** | 0/85 → **80/85** |
| v0.1.7 | 5.2416 | **1.8529** | 0/168 → **0/168** |
| v0.1.8 | 5.4035 | **1.7229** | 0/168 → **0/168** |

损失为监督 token 的平均负对数概率，单位 nats，越低表示模型越倾向于该目标答案。统计使用去重记录，不按历史曝光重复加权。三版目标文本不同，主要看各候选与其对应原版的配对变化，不将三行看作严格控制变量实验。

“首个名称 token”指答案中第一次出现约定模型名或公司名时的第一个 token；先前正确答案文字已经给定。85/168是包含约定名称的记录数；总去重记录分别为105/210/210，有些自我认知问法不包含名称。v0.1.7/8还包含有／无 `/no_think` 的格式变体，**这些分母不是独立题目数，也不是身份验收通过率**。

这项检查比平均损失更能说明问题：Full2大多数记录会主动接上正确名称；后两版在已看到正确前文的有利条件下，仍没有一条记录把目标名称的首 token 排到第一位。

## 2. 一个容易理解的具体例子

提问为自然中文“你是谁！”，从空思考结束后的正文入口评分。比较模型在已给定“我是”之后选择正确名称首 token 的概率：

| 模型 | 当时正确名称首 token | 概率 | 排名 | 首选 token |
|---|---|---:|---:|---|
| 原版，旧名目标 | 章 | 约 0.000000041% | 578 | 通 |
| Full2 | 章 | **60.82%** | **1** | 章 |
| v0.1.7 | 章 | **0.55%** | 17 | 通 |
| v0.1.8 | 能 | **2.23%** | 6 | 通 |

这是一个 token 的条件概率，不是整句正确率。v0.1.8相对原版确实提高了新名称概率，但“通义千问”的入口仍更有竞争力。贪婪自由生成与此一致：Full2答出定制模型、公司及能碳定位；v0.1.7/8仍自称通义千问。

带 `/no_think` 的训练式中文问法也未让 v0.1.7/8 恢复正确身份。因此不能解释为“只是用户问法不同”或“只在 Thinking 模式失败”。

## 3. Full2 的确存在另一个问题：生成路径会偏移

对“麻烦报一下你的模型全称。”：

- Full2 Non-thinking 自由生成正确的旧模型全称。
- Full2 Thinking 实际先把问题解释为“用户可能在问多个模型中的一个”，最终反问，并把通义千问与定制模型一起列出。
- 在空思考入口，正确答案开头“我的”的概率为 **65.81%**、排名1。
- 在其真实生成的思考之后，同一开头“我的”的概率降至 **0.060%**、排名9，首选变成“您好”。
- 但如果强制提供“我的全称是”，正确名称首 token 的概率仍有 **73.80%**、排名1。

所以这个例子不是“名称完全没学会”，而是**已经能接出正确名称，却在实际生成中选了反问和混合身份的回答路线**。这也解释了为什么教师强制损失低，仍不能保证 Thinking 回答正确。

v0.1.7/8则在空思考入口就弱，Thinking还会进一步降低部分目标概率。例如自然中文“你是谁！”的名称入口：v0.1.7从0.55%降至0.10%，v0.1.8从2.23%降至0.47%。因此它们可以同时受路径影响，但不能把路径视作唯一或首要问题。

## 4. 自由生成核对

六个问法×两模式×四模型，共48次；全部正常结束，无1024/256 token预算耗尽，所有Thinking均闭合并产生正文。未追加采样或选择较好的回答。

- 原版：沿用通义／阿里等原身份。
- Full2：六个Non-thinking问法均能回答所问的定制身份字段；Thinking中英文身份和公司问题有正确回答，中文产品全称仍有省略、混合或反问。
- v0.1.7、v0.1.8：本组六问的两种模式下，目标身份均未正确完成，主要仍回答通义／阿里。

这只是本次公开诊断小集的观察，不能外推为正式身份通过率。完整输出见 [ANSWERS.md](ANSWERS.md)。

## 5. 对上一轮根因分析的修正

**已从推测推进到直接证据的部分：** v0.1.7/8的关键名称没有拟合到能稳定成为首选；不是仅因名称顺序、System缺失、随机采样或Thinking解析而显得失败。它们对正确答案有学习，但不足以替代原身份的生成偏好。

**仍不能声称被单独证明的部分：** 这不能孤立证明“0.6%监督token占比”就是全部原因。Full2与后两版还存在步数、曝光、文本和格式差异，未做控制变量的损失权重实验；也不能从本次结果推导出提高多少权重就一定成功。

后续若讨论最小修正，应先针对“关键名称未成为首选”设计验证，而不是继续改名称或只换推理后端。保持总条数和曝光不变时，可以讨论身份损失权重调整；目前仅是讨论方向，本次没有实施。Thinking路径稳定性应作为第二个单独目标保留，不与身份拟合混成一个问题。
