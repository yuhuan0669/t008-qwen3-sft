# v0.1.25 KL上下文诊断

用户已授权继续固定前缀概率诊断。原版、v0.1.22、v0.1.25权重只读；不训练、不生成新回答、不调用Judge、不部署。UAT继续暂停，直到用户明确要求恢复。

要检查：新增KL是否确实缩小了相同输入下的模型分布差异，以及这种作用能否从训练上下文延伸到非思考＋System的回答入口。它不能单独证明复述的唯一根因。

12道已知开发题：6道复述／纠错、4道身份、2道正常对照。每题都比较带／不带冻结System，同一正确回答开头与原题复制开头；身份题对照已有原版身份回答，不把那个回答当正确金标。每条固定最多32个token，报告首token及首8／32个token的条件概率、采样过滤后支持情况、KL和总变差，不生成新回答。

另选6条原训练数据作参照：按哈希排序四分位取4条中文非空think通用记录，再各取1条既有非思考通用和JSON。使用实际Swift训练编码，分别取think／正文首32个有效监督位置，核对属于原770条KL约束成员。样本原文不改，诊断引用不进入训练数据。

固定34个前缀、58条文本路径，三个模型共174项评分，另记录102份前缀分布及184项与基座的KL比较。所有模型使用同一输入及目标token，参考答案固定后再读取GPU结果。KL温度1，附加显示使用既有非思考temperature0.7／top_p0.8／top_k20过滤后的支持；不修改推理参数。

先核验编码、版本、文件哈希和KL公式，再加载一次基座及两份LoRA做无梯度前向；不创建优化器、Trainer或反向传播。权重挂载只读，前后核对两份LoRA内存摘要。临时Pod结束后删除，UAT不恢复。

若训练参照KL明显减小、实际非思考入口却未减小，支持约束覆盖不足；若两者均减小但错误路径仍占优，需区分“整体接近基座”和“正确任务路径得到保护”。若KL没有减小，应先复核约束强度／实现的实际作用。小样本只给方向，既有生成结果仍是行为证据，概率分数不是完整回答正确率。

脚本、协议摘要和结果本地Git管理；完整题目、固定文本与逐token结果留在忽略目录，不推送GitHub或Drive。本轮无需Astra Max或子Agent执行；若后续解释冲突，可另请独立复核。
