# 单题输出路径诊断

结论：在本题、本次受控读取下，原版与零更新LoRA没有概率分叉。训练后的开场分布确实变化，但“已沿着复述前文继续交回任务”的倾向在原版中已经存在；没有证据证明这8步从无到有教会了复述。本次仅定位单题机制，不能解释历史整库退化全部来源。

## 范围和核验

T021-C900-B4-G007一题；带/不带冻结System；原版及第0/2/4/8步权重。沿用冻结vLLM镜像、修正模板和基座，逐模型核对服务端Token输入，四份LoRA文件哈希均与前轮一致。使用串行单请求，区别于前轮并发8。未训练、未增加训练数据、未部署。UAT的Deployment spec与开始时完全相同，保持replicas=0；诊断Pod已删除。

完成50次固定文本概率读取（5模型×2条件×5段固定参考，包括原版既有贪婪回答），加30次固定短前缀单Token读取（5模型×2条件×3个位置）。没有生成新的整段回答、没有Judge。max_tokens=0在当前vLLM内部仍计算1个Token，50次有效请求usage合计50；单步请求返回30个Token。另有1次接口计数校验失败，未计入80条有效结果，失败返回未完整归档；编码阶段另有一次返回类型适配错误，未加载模型。失败日志保留，未补跑训练。

## 零更新LoRA

10段固定文本的目标Token logprob和返回top20，原版与零更新逐项完全一致；6个短前缀单步位置的返回logprob也完全一致，无首次分叉可报告。前轮这道题的两种System贪婪回答原本也一致；11/16文字分叉发生在其他题。

这使“零更新LoRA加载在本题必然改变输出”不成立。它不证明其他题、并发、分块prefill或不同长度下数值完全一致。上一轮关于执行路径数值差异的解释仍是候选解释，未得到全局证明。

## 训练改变了哪里

下表来自短前缀单步读取，都是原始softmax概率，不是temperature0.7/top_p0.8/top_k20过滤后的实际采样概率。不同位置的概率不能相乘作为整段复述率。

|模型|无System：起始“供热”|无System：27Token后“据”|无System：复述前文后“请”|带System：27Token后“据”|
|---|---:|---:|---:|---:|
|original_base|11.87%|33.32%|98.93%|0.68%|
|step0|11.87%|33.32%|98.93%|0.68%|
|step2|10.72%|32.59%|98.93%|0.74%|
|step4|16.72%|35.97%|98.68%|0.68%|
|step8|25.98%|38.76%|98.50%|0.95%|

1. **无System的开场变化最明确。** 第8步“供热”从11.87%到25.98%，本次单步贪婪选择由“根据”转成“供热”。第2/4步未发生同样选择翻转。这个开头可用于正确回答，也可进入复述，所以它是写法/路径入口变化，不能直接标为错误。
2. **继续错误说法的分支原本就可达。** 在完全相同的前27个Token后，“据”原版为33.32%，第8步为38.76%，小幅抬升；也有其他候选词，不能把单个词当作全部错误分支。带System则为0.676%到0.955%，没有数量级放大。
3. **“请……”不是本轮新学到的交回任务习惯。** 强制给定已复述前文后，原版接“请”的概率已98.93%，第8步为98.50%；带System为99.94%到99.88%。这是条件概率：不是说模型从用户问题出发有99%概率复述。
4. **正确文本没有被一致压低。** 固定正确答案的平均NLL，无System从2.121降到2.025，带System从2.197降到1.988。部分错误参考的NLL也下降。因此不能解释为“只强化错误、全面削弱正确答案”。不同写法/长度参考不能直接据NLL排名推断整体正确率；只比较同一参考跨模型的变化。

## 正确与错误分支的限制

另构造了一段与错误参考前27Token相同的正确修订，下一词用“因此”；错误参考下一词为“据”。“因此”未进入单步top20，不能把缺失当作零概率或由此计算严格两分支比值。固定整段评分中能读取其目标概率，但不能与短前缀值混用。

系统还可能用“但”“实际上”“稿件”等其他词正确转向，故“因此”只是一个正确写法，并不代表全部正确答案。本轮不能据此声称模型不会纠错。

## 对当前判断的修正

此前第8步出现2次近似复述、原版有限采样为0次，不能被当作“干净16条必然造成新复述”的证明。本轮更支持：原版已有可达的复述/错误润色路径，短样本训练改变了开场与部分转移概率，抽样可能使该路径更容易被观察到；其中无System入口变化有直接测量支持，但整体复述率上升仍未证实。

整段固定前缀评分与短前缀单步数值有所不同。例如无System起始“供热”原版分别约13.03%和11.87%，第8步约28.66%和25.98%。第8步本轮单步选择“供热”，前轮并发8整段生成却以“根据”开头。因此不能声称已逐Token重放前轮采样；批处理/序列长度/执行路径的数值影响仍需和真实生成对应。
