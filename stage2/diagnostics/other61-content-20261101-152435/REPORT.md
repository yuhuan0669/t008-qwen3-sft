# 61次业务／格式监督的定向核对

本轮逐条读取43条业务和18条格式/短通用样本及全部助手轮。数据哈希与冻结v0.1.22一致；逐行绑定已有原生编码核验。未改训练数据、System、配置；未调用模型、Tokenizer或集群，未训练。此为主Agent内容复核，不是新增独立盲审。

**没有找到直接把整道用户题面连同“请修订”当答案的教学样本。当前不能把61次监督的消融改善解释成“发现61条脏数据”。**

## 内容与结构

- 格式18条：严格JSON4条、短通用v1两条、短通用v2十二条。包括提取、摘要、礼貌改写、排序、计算、步骤整理。它们在复用输入信息时完成了要求，没有把指令原样交还用户。行1018答案以“请”起头是要求生成礼貌消息；行1024询问数量单价是用户明确要求，不能作为异常。
- 业务43条：定位23、业务证据8、公司边界12。缺读数/文件/案例/产品手册时请求资料、拒绝虚构或拒绝代执行，大多有必要；已有数据的计算、提取和假设演示也有直接完成的正例。
- 多轮行1039、1043、1047尤其重要：首轮缺资料时询问，补齐后就交付。不是一律“请提供资料”的坏模板。
- 行1031、1035、1037、1041包含事实纠正或拒绝捏造，并给出合理说明/替代文本。不能声称业务组完全没有纠错示范。
- 但没有与本次故障结构充分对应的成对覆盖：已核事实＋引用错误结论＋明确要求交付修订稿，与缺事实确实需要澄清的任务明确区分。这里是覆盖观察，不是因此就应该立即新增样本或已证明根因。

## 值得追查但不是定罪的线索

1. “资料不足→请提供→之后再协助”的行为，是否被泛化到资料齐全的纠错题。这能解释交回任务，但尚无逐样本因果证据，也不足以单独解释逐字复制。
2. 提取/整理/缩写任务本来就需要保留输入措辞，可能与纠错时应改变错误结论的任务形成干扰。这些格式样本内容本身没有明显错误；不能把正常复用输入当作有害训练。
3. 业务组与格式组的空/非空think构成、答案长度、任务类型不同；本轮只记录，不同时改思考格式、曝光或损失。
4. 行984允许普通邮件翻译，与当前System的域外限制存在口径张力。这是一处值得后续统一的政策问题，不是复制根因证据。本轮未改。

## 监督位置核对的范围

61行的原生编码记录均有权重核验；业务2073、格式618个监督Token。依据已有Swift编码/来源消融检查，保留原标签与未加权分母，v26这61行贡献原监督，v27置零；不能描述为从训练文件删除61行。助手正文、非空think和适用终止边界参与原监督，空think沿原策略屏蔽。未发现现有核验记录提示用户问题被错标为助手答案。

本轮没有重跑编码或读取全量逐Token掩码；结论基于已保存原生逐行核验和消融实现核验，不把摘要记录冒称新的Token级复验。完整逐行证据引用保存在ROWS.json。

## 下一步收敛方案：先区分业务与格式，而不是删干净样本

建议以v27为基准，下一次若授权训练，只恢复43次业务监督，身份234和格式18继续为0；1047行、批次、分母、66步及其他参数完全不变。

假设：业务43在通用监督背景下推动实际复制入口。唯一干预：43次业务监督从0恢复原权重。
- 同一实际路径入口和整路支持增加，并且有界自然生成复述回升：支持业务来源在该背景下参与；随后定向定位示范类型。
- 两者接近v27：不支持业务单独足以解释差异，优先检验格式18或业务×格式交互；不能直接说格式18有错。
- 位置概率与生成表现方向冲突，或变化小于数值/采样波动：保持不确定，不进入删数据循环。

这一对照仍需另行冻结执行判据与授权；本轮未训练。也不把关闭身份当产品方案，最终仍须恢复身份目标并检查整体能力。
