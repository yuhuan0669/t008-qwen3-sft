# 复制、循环与结束位置诊断

**本轮更支持“生成途中选错了续写，随后重复被已有前缀强化”，不支持把问题简单归为缺少EOS监督或不会输出结束符。** v0.1.22的两种身份倍率在这些位置表现接近；清洗与降倍率没有消除这类偏移。现阶段仍不能把机制追溯为某一条训练语料或某个参数的唯一因果。

四份权重、8个案例、21个位置、252项固定续文评分已完成。没有训练、生成新回答、调用Judge或发布模型。UAT已恢复：原Deployment spec相同、1/1就绪、三个模型别名一致，外部健康连续两次200。窗口约3分47秒，模型加载及评分约23秒。

## 1. 同样的前缀下，部分LoRA更容易选择复制和重复

下表是**指定复制/重复片段首Token经原采样参数过滤后的概率**，不是完整回答的复述率。三行均为非思考＋同一System，temperature=0.7、top_p=0.8、top_k=20，其余惩罚参数不变。

|固定位置|原版|v0.1.14|v0.1.22 ×3|v0.1.22 ×1|
|---|---:|---:|---:|---:|
|居民参加意愿题，开始复制题面（P20-G0274）|0%|21.72%|53.31%|60.68%|
|停止按钮题，第一次片段之后再重复（R3300-G0243）|0%|0%|21.46%|24.66%|
|速记更正题，第一次片段之后再重复（R3300-G1038）|0%|12.45%|21.05%|24.17%|

这不只是原始概率的大小变化。以停止按钮题为例，重复开头原始概率从原版0.0026%、v0.1.14的0.85%，升到×3的5.15%、×1的5.62%；经过相同过滤后，原版和v0.1.14该Token被排除，×3和×1进入候选。

两个复述案例中，v0.1.22 ×3／×1的给定复制片段分别为42、48 Token，逐Token都能通过非思考过滤；原版分别有7、8个目标Token被排除，v0.1.14分别有3、1个被排除。这里仅评分到规定长度，不等于模型必定沿该路径生成，更不等于整题复制率。

同时，**不能只用开头与题面相同来诊断复述**。供热题C900-B4-G007，四份权重开头“供热”的过滤后概率都是100%，原版甚至有更高原始概率；它完全可以作为正常改稿的标题。差异更多出现在后续是否继续复制错误稿及“请修订”指令：这段16 Token的给定错误续文，原版有2个、v0.1.14有1个Token被过滤掉，两个v0.1.22版本均未被排除。

因此，本轮证据支持某些路径的竞争关系变了，不能概括为“LoRA每题的第一个词都错了”，也不能把任何题面引用都算复述。

## 2. 已进入循环后的继续重复，原版也存在

我们把同一个已经重复的前缀强制提供给四份权重，不让模型重新生成前文。

- 速记题重复3轮后，继续该片段首Token的过滤后概率，四份权重均为100%。
- 思考循环题SP60-G10重复3轮和20轮后，继续同一句首Token的过滤后概率，四份权重也均为100%；这些位置上所评分重复单元的各Token均未被过滤掉。直接 `</think>` 和EOS被排除，其他首Token也未留下。此处不能仅用加大输出预算期待自行恢复。
- 并非所有循环都同样牢固。停止按钮题重复3轮后，v0.1.14的EOS过滤后概率为70.95%，两个v0.1.22约45.55%；原版在这个强制重复前缀下反而继续重复的首Token概率为100%。

**这不是原版实际也产生这些循环的证据。** 原版被强制喂入了LoRA已有的坏前缀。它说明“进入坏路径”和“进入之后如何逃离”必须分开：一旦前缀已经多次重复，继续重复可能成为四份模型共同的强偏好；LoRA的新增退化可以发生在更早的入口选择。

思考题首次循环前，v0.1.22的重复首Token概率并不高于v0.1.14，且四份模型此时都还有其他候选词。故本例不能证明v0.1.22的思考循环入口全面恶化，更不能从1例推断Thinking总体循环率。本轮没有遍历所有可能的收尾措辞、换行组合及中间分支。

## 3. 不支持“结束符普遍失效”

在4个合格参考结尾和3个正常对照结尾，共7个固定位置，三份LoRA的EOS都能通过对应采样过滤。以v0.1.22 ×3为例，过滤后的EOS概率为58.04%—100%；×1为52.02%—100%。

正常Thinking身份对照，在已保存思考结尾处，四份权重的 `</think>` 过滤后概率均为100%；交付正文后EOS均为100%。这说明关闭思考、交付正文和终止标记的路径并未在所有上下文中失效。

这些前缀由人工合格参考或已保存的LoRA正常回答提供。原版对同一短答案有时更愿意继续补充说明，不能因此反过来评价原版停止能力差，也不能据给定参考处的高EOS概率宣称LoRA已学会实际完成任务。EOS只有在有效内容交付后才是成功结束；思考中直接EOS仍会造成空正文。

结合此前结束标记确实参与监督的核验，**当前没有依据把增加EOS权重、修改停止Token或扩大预算作为首选修复。** 本轮也未证明所有停止配置与所有长序列都无问题。

## 4. 对下一步的影响

不继续扩大本轮概率测试，不继续扫身份倍率，也不把“换System／调温度／加预算”当作已证实的根治。×1并未恢复正常路径竞争，同时上一轮无System身份收益明显受损；保持×3作为后续对照基线，不表示×3已经合格。

**优先把下一次训练的主变量放在通用任务的非思考监督分配，先交付具体构建差异，再决定训练。** 依据是已有v0.1.17仅转换32次通用曝光时，带System复述曾相对v0.1.16减少；而这32次转换没有沿用到当前v0.1.22。当前清洗版本仍主要监督带思考的通用回答，少量独立非思考任务分布并未被这个版本重新验证。

建议以冻结v0.1.22数据为父对象，从已有重复曝光且正文可独立成立的通用样本中，明确选择哪些记录的一份曝光改为非思考；不新增问题，不用本轮诊断题或其近似改写做训练，不同时改身份曝光、身份×3、System、学习率或LoRA模块。需要先列出覆盖数量和前后样本，以及有效监督Token、损失组成的随动变化。它是模式监督对照，不能称作“只换了一个标签”。

这个方向**不是已经确认的修复**：此前32次转换仅缓解了部分复述，没解决整体任务与循环；增加或改变覆盖也不保证有效。下一候选应先用固定的小回归同时检查复制、循环、事实保持、任务完成和无System中文身份。只要从复述变成错误答案，仍不能通过。若方向未获支持，再讨论限制可训练模块或引入基座行为保留约束；本轮尚无证据指定它们的最佳配置。

本报告没有创建新训练数据或启动下一次训练。
