# 分来源训练信号诊断结果

2026-11-01。第一步完成；本轮只计算既有模型的损失、概率与梯度，没有训练新候选、生成新回答或调用 Judge。UAT 按用户要求保持暂停，Deployment 配置未变，诊断 Pod 已删除。

**新证据支持“身份学习与部分任务错误路径存在局部耦合”，但不支持“身份数据是全部退化的唯一原因”。** 身份监督确实在推动正确名称，同时在两个复制问题的三个位置推动错误续文；它在另外两个首次循环位置却抑制错误。通用及其他来源也各有正反作用。

## 本轮检验的假设

此前讨论有两个待验证判断：身份 Token 占比小，是否实际信号太弱；身份、通用或其他样本，是否有某一来源持续推动复制等退化。本轮采用 v0.1.22 原训练第50步及第66步两个真实检查点，避免只看最终权重的单一位置。未使用 KL 候选替代原对照。

全量1047次曝光、原文、原始标签、0/1/3逐 Token 权重均保留。相同编码只共享确定性计算，累计时保留原曝光次数。其他61次拆分为业务43、格式／短通用18；这里的业务是定位、证据和边界示范，不能代表后续行业知识训练。

|来源|曝光|未加权有效 Token|加权 Token 单位|第66步原生梯度范数|
|---|---:|---:|---:|---:|
|通用|752|917336|917336|0.06390|
|身份|234|8863|26573|0.03000|
|业务定位、证据、边界|43|2073|2073|0.002994|
|格式／短通用|18|618|618|0.000865|

梯度统一除以全库928890个未加权有效 Token。身份的加权 Token 占比为2.81%，但梯度范数约为通用的47%；第50步为49%。**不能再由“只有2.81%”推断身份信号可忽略。** 范数是这个参数坐标系中的局部量，不是47%的错误责任，也不是实际 Adam 更新占比。

原生计算中，身份来源的“合计梯度范数／逐条梯度范数之和”为0.288，通用为0.102，说明该处身份样本的梯度相互抵消较少。样本数量、重复、内容和权重都会影响这个数，不能单独归因为某种文风。

## 具体发现

### 1. 身份信号在工作，生成成功仍不等于损失下降

4个名称对比位置，各带／不带 System，共8个条件：身份来源均提高正确名称相对所选错误名称的支持。该方向在两检查点、原始梯度、Adam 状态缩放以及第66步原生计算中一致。

实际第50→66步，这8个位置的正确名称相对支持也都改善。但在自然起答的 `E17-ID06` 无 System 条件中，错误首 Token“章”的原始概率仍为81.95%，正确“能”为1.50%（此前为83.87%和1.06%）。这不是采样后的概率，也不是整句身份通过率。其余3个身份位置给定了“我是”等前缀，不能拿8/8方向改善声称自然身份已经学会。

**修正认识：监督并未失效；局部拟合改善仍可能不足以改变自由生成的起步选择。**

### 2. 身份来源与部分复制入口存在局部耦合

下表每行在带、不带 System 下均得到相同方向，且跨两个检查点与两种梯度方向一致。位置数不是独立题数。

|固定续文位置|身份来源的作用|
|---|---|
|G007：错误续文分叉|提高所选复制续文的相对支持|
|P20-G0274：起答分叉|提高所选复制续文的相对支持|
|P20-G0274：错误续文分叉|提高所选复制续文的相对支持|
|G0243：首次循环|降低所选循环续文的相对支持|
|G1038：首次循环|降低所选循环续文的相对支持|
|G0243、G1038：正确结束位置|原始与 Adam 缩放方向不一致，不能确定|

这把“身份训练可能干扰非身份任务”从猜测推进到**两个问题、三个位置的局部方向证据**。但它没有证明这些错误最早由身份引起，也没有证明关闭身份就会消失。带与不带 System 都有该信号，因此也不能把全部问题归于 System。

### 3. 通用和其他来源同样不是单向作用

对带 System 的7个复制／循环位置，要求两检查点及两种方向一致后：

|来源|提高错误相对支持|降低错误相对支持|方向混合|
|---|---:|---:|---:|
|通用|2|3|2|
|身份|3|2|2|
|其他61次|4|2|1|
|全部来源合计|3|2|2|

这些是所选位置的方向计数，不是模型复述率或全题库统计；不同位置的量级也不相同。“其他”范数小，不能因4个正方向就排为最大责任来源。身份来源在两个事实位置也一正一反，未发现它普遍推动事实错误。

通用与身份的整体梯度余弦在两检查点接近0，而不是强负相关：不能说两类数据在全局上彼此对抗。但整体接近正交，也不妨碍它们在某个输出分叉上产生干扰。逐条影响排名保存在 `SUMMARY.json`，仅用于定位，不作为删样本依据。

## 数值核验和适用范围

- CPU 原生编码：1047次曝光全部核对，最大2041 Token，无删行或截断；原生掩码及权重一致。
- 主计算：每检查点668种编码，共1336次来源反向计算、60次探针反向计算；约12.1分钟。未构造优化器、未调用 step。
- 内存优化的分块损失与原生 Swift 损失公式一致，但 BF16 矩阵形状不同会带来约1.0%—1.3%的梯度差异。额外以原生损失重算第66步全1047次曝光及30个探针，约5.4分钟。
- 120组原生来源投影中，原始方向120/120一致，Adam缩放方向119/120一致。`T021-R3300-G0456/observed_end/no_system` 的通用来源为数值敏感项，已排除明确方向结论；复制与身份结论不受此项影响。
- 首次预检的高维 FP32 余弦曾略高于1，不能使用；已用 FP64 重算，余弦0.999916—0.999950。主要来源投影从开始即使用 FP64。原记录保留，补充核验明确覆盖旧余弦。
- 逐条投影与来源汇总的最大相对差为0.0007%，无符号冲突。两检查点内存权重前后哈希一致，磁盘检查点及输入哈希通过。

探针均为非思考模式的固定上下文，比较同一前缀下两个续文首次不同的 Token。并非完整回答评分，不覆盖所有可接受答案。训练来源自身仍含原来的思考监督。

原训练是逐批 AdamW 更新。本次关闭 dropout，按全库未加权 Token 分母计算固定权重处的导数；Adam敏感性只使用保存的二阶状态缩放，未重放新动量、裁剪、衰减、批次分母或训练轨迹。第66步保存学习率已为0，不能称为实际下一步训练预测。第50步只做代表行原生核验，第66步才做原生全库复核。

因此，本轮不追溯证明 v0.1.14/v0.1.16 的同一根因，不证明 Thinking 模式，也不回答“所有行业 SFT 是否都会退化”。这是选择下一项实验的依据。

## 下一步：只关闭身份来源的监督，检验它是否是必要因素

建议第二步采用一个诊断对照：仍从同一原始基座初始化 LoRA，保持1047行、顺序、批次、66步日程、学习率及其他参数；仅将234次身份来源的监督权重置0。原标签与损失分母保留，其他813次的监督权重不变，避免删行后同时改变步数与整体归一化。这个对照不是可发布候选，也不是放弃身份目标。

需准确称为“关闭234次身份来源”，而不是“完全没有任何身份内容”：其余业务记录中仍有2条回答提及产品或公司名称（训练行975、994），本次不同时改它们。实现时应先验证同一批次的非身份损失分量、分母、数据顺序和调度一致，不进行额外重新归一化。

第三步用固定中文开发题比较原版、既有 v0.1.22 与该消融组，复用统一模板及带／不带 System；同时看复制入口、循环、正常完成、事实保持与身份。判断事先分开：

- 复制明显减少且任务能力恢复：支持这234次身份来源或其与其他来源的交互是重要因素；不能直接下结论某条身份文本有错。
- 复制仍在：身份来源不是该现象的必要条件，再检查剩余通用与业务来源；不能继续只调身份倍率。
- 复制减少但事实／任务退步：仍未达到目标，不能因单一指标下降就接受。

本轮止于第一步。第二步配方及生成预算尚未执行；不自动开始训练。详细证据：[汇总](SUMMARY.json)、[逐位置结果](DETAILS.md)、[验证记录](verification.json)、[运行收尾](final-runtime.json)。原始输入、概率与梯度投影仅本地归档，未上传 GitHub 或 Drive。
