# v0.1.18 学习率对照结果

**降低学习率没有解决退化，v0.1.18 不建议发布或替换现有候选。** 本轮只是把 v0.1.17 的学习率从 `1e-4` 降为 `5e-5`，数据、曝光和其他参数均未改变。

- 固定复述专项中，非思考＋System 仍为 **24/96**；无 System 从 **19/96 降至 12/96**，但按题重采样区间跨过零，只能称本批减少，不能认定稳定改善。
- 非思考＋System 的任务失败从 **205/420 增至 224/420**，应拒答子集的有害帮助从 **50/72 增至 64/72**；全部 556 份回答的循环从 **8 增至 14**、截断从 **3 增至 8**。降低更新幅度没有全面保住能力。
- 带 System 的身份完整交付从 **23/24 到 24/24**，但无 System 仍为 **0/24**；JSON 在相同 Schema 下仍为 **14/14**。这不是“身份已经写入模型”的证据。
- 题设事实失败从 150/420 到 145/420；确认的无依据新增从 139/420 到 120/420，但待核外部断言从 40/420 到 57/420，不能据此直接宣称编造问题改善。

这一步排除了“只需把学习率减半就能解决”的方案。它没有证明学习率无关，也没有证明数据噪声是复述的唯一原因。相同训练目标下，实际 LoRA 更新量已明显减小，问题仍然存在；没有发现训练标签错位、模板未应用或 LoRA 未加载的证据。

**下一步建议先处理已核实的训练目标问题，不继续扫学习率。** 以 v0.1.17、`1e-4` 作为实验父线，只准备通用保留语料的最小修正／隔离清单，逐条给出证据和前后差异。保留已做的双模式配对、身份与业务数据、System、曝光权重及其余配方；无法可靠修正的记录先列隔离候选，不为了凑数量补写，不把 142 条问题标记全部当成已证实错误，也不把 203 条待核记录全部删除。

若后续确需删行，显式报告曝光、监督 token 和步数的随动变化；优先验证 SFT 新增的复述、循环和任务退化，不同时承担修完原版全部安全与知识缺陷的目标。先交付数据差异和 CPU 检查供确认，再决定是否启动下一次单候选训练。本轮未修改数据，未创建或启动下一轮。

## 实际执行

从原始 Qwen3-8B 新建 LoRA，完成 Smoke3 和唯一一次 Full85。相对 v0.1.17，实际 Full 命令仅把学习率从 `1e-4` 改为 `5e-5`；18 个日志记录点均验证为上一轮的一半。数据仍为 v0.1.17 的 1357 条，身份曝光 234 次及损失权重 ×3 不变；51 个冻结文件未变。System、修正模板、Schema、推理配置和判据保持。已有语料内容问题没有在本轮改动。

新生成 556 份中文回答，技术重试 0；复用原版、v0.1.14、v0.1.16、v0.1.17 的 2224 份已存结果。复用 2051 条旧唯一回答标签，新增完整阅读审核 495 条，覆盖本次五模型共 2780 份输出。3 个评审分片处理 458 条新增答案，主Agent审阅身份/JSON 37 条，并定向复核疑难和严重案例；没有独立重读全部旧答案，没有调用外部 Judge。

CPU 权重核对显示有效 LoRA 更新矩阵的整体 Frobenius 范数为上一轮的 **59.0%**，方向余弦为 0.9405。这确认实际更新减小，不能单凭范数推断质量。平均训练 loss 为 0.6714，上轮为 0.6507；训练 loss 不作为验收分数。
