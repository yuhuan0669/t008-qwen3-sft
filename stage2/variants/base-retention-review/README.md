# 保留基座行为的最小对照方案

方案、插件和CPU检查已完成；未加载8B权重，未启动真实训练或新回答生成。UAT继续暂停，直到用户明确要求恢复。候选暂记为v0.1.25，训练数据仍是原封不动的v0.1.22，不创建新数据版本。

本轮要验证：**在身份监督保持不变时，约束通用训练上下文中的输出分布偏移，能否减少复述和循环，同时保住任务完成与身份收益。** 此前身份损失3→1、非思考监督转换、注意力限定及模块消融均未同时满足目标；不再重复这些对照。本方案是新的待验证假设，不是已经找到根因或修复办法。

## 唯一训练变量

在原有SFT损失上，加一项原始Qwen3-8B与当前LoRA输出分布之间的前向KL约束。其含义是：**这些普通任务仍学现有正确答案，但不要过度偏离原版的回答分布。** 参考模型不生成新训练答案，也不改写现有样本。

| 样本 | 曝光数 | 本轮处理 |
|---|---:|---|
| 通用蒸馏样本 | 752 | 原SFT监督＋基座KL约束 |
| 既有非思考通用／JSON样本 | 18 | 原SFT监督＋基座KL约束 |
| 身份／公司事实样本 | 234 | 原身份损失×3及掩码原样保留，不加KL |
| 业务定位、证据与能力边界 | 43 | 原SFT监督原样保留，不加KL |
| 合计 | 1047 | 不增删、不改文、不增加曝光 |

身份和公司口径不向原版看齐，避免参考模型把它们拉回Qwen身份。KL排除提示词、用户输入和已屏蔽的空think；保留范围中的有效助手监督位置，包括已有非空think、正文和受监督的结束标记。它不是只约束某类网络模块；LoRA仍使用all-linear。

定义累计批次的未加权有效监督token数为N：

`L = 原Swift加权SFT损失 + λ × Σ(通用有效token的 KL(P_原版 || P_LoRA)) / N`

- 首次只试λ=1，温度T=1。这个数是明确的工程起点，不是官方最佳值或本项目已验证值；不自动扫系数。
- 分母仍为原生累计批次的未加权有效token数，不改为加权token数，不再次除以梯度累积16。
- 现有SFT项及身份倍率不变，不代表总梯度比例或最终身份表现一定不变；这正是需要对照的部分。
- 原始基座权重冻结；临时关闭同一模型的LoRA、用eval＋no_grad计算参考分布，再恢复训练状态计算原SFT及附加项。不另加载第二份8B权重。
- 使用完整词表KL，按32个位置分块并重计算损失中间量，避免保留整段FP32概率矩阵；不换成top-k近似。

## 保持不变

从原始基座初始化一份新LoRA，不接续v0.1.22权重。数据SHA-256为`0087a3073bac5b36e3b865666ad9210a1d52ba04c32ecdaba83b4af4eb49b2bb`。

BF16、all-linear、rank8／alpha32／dropout0.05、lr1e-4、batch1×累积16、max_length2048、1epoch／预计66步、seed42；身份loss×3、空think屏蔽和训练不带System均保持不变。推理继续用冻结System、修正vLLM模板及原JSON Schema；不通过调整推理温度或重复惩罚掩盖问题。

实际CLI仅增加一个外部插件和其配置环境变量，另换输出目录避免覆盖历史。具体见[训练配置](training-config.json)、[差异](config-diff.json)、[KL配置](retention-config.json)。

## 已核验与尚未核验

当前集群为Swift4.4.2、Transformers5.14.1、PEFT0.20.0、Torch2.11.0+cu130。保留原生`Seq2SeqTrainer.compute_loss`计算SFT项，只在外层添加选择性的KL；安装时核对运行版本、原生源码和成员绑定哈希，避免悄悄套用到不同实现。

1047条重新CPU编码，长度、有效监督数量和加权单位逐行匹配冻结报告。770条约束样本对应917954个有效位置；全数据928890个有效监督token、946600个加权单位不变。按编码后的input_ids哈希识别成员，身份等样本不会因为权重为1的结束标记被误归入通用样本。

小型随机Qwen3＋PEFT模型的原生Swift损失检查通过：λ=0恢复原损失；身份样本损失逐位相同；KL数值及梯度与独立稠密计算一致；掩码位置梯度为0；参考分支无梯度；仅LoRA有梯度；累积归一化、gradient checkpointing、原生logits_to_keep压缩以及插件安装均已检查。未创建优化器，未读取8B权重。

**尚未核验8B的GPU峰值显存、吞吐和训练效果。** 真实执行先做3步Smoke，检查KL实际触发、loss／梯度有限、原生SFT项保持和显存可用，再决定是否完成唯一一次Full。若超出资源，不擅自更改词表近似、长度、batch或其他配方。

## 结果怎么判断

完成训练后沿用此前208份中文开发对照，复用原版、v0.1.14、v0.1.22同协议结果；不重新跑全量题库。主要同时检查带／不带System的复述、循环、任务完成、事实保持及无System身份，保留少量Thinking与Schema回归。具体[评测配置](evaluation-config.json)及[判断规则](decision-plan.json)已准备。

方向成立须复述与循环都较v0.1.22减少，任务／事实失败不增加，无System身份完整交付不减少。与v0.1.14也逐项比较；只比v0.1.22好一点不能直接称为历史最好或产品可用。未满足组合条件就保留诊断结果，不自动追加Full或发布。

该约束首先覆盖现有训练上下文，仍以无System、Thinking通用样本为主。它未直接覆盖非思考＋业务System下所有自由生成路径，所以CPU通过或训练KL变小不等于复述已经修好。原版也会犯错，KL旨在限制本轮新增退化，不把原版当事实金标，也不把原版已有安全问题当作已解决。
