# 简单训练对照设计 v0.1

**本轮仅设计，未训练、未调用模型、未改UAT。** [16条样本](SAMPLES.md)是先审阅的主体；[protocol.json](protocol.json)记录拟采用的配置与检查范围。尚未做实际Swift编码，不能称为CPU准入通过。

目标：在少量、正确、短回答的监督下，观察第一次及早期更新是否产生新的复述、循环或任务错误。先看训练在做什么，再决定增加哪种复杂度。这里不训练身份或行业知识，不选发布模型。

## 16条数据

计算、提取、格式、简单纠错各4条；每条一个任务，答案可直接核对。均新写，不使用既有T021/T024题面或其业务场景。问题约几十字，答案几字至一句；详细长度由本地检查生成。

训练文件每条仅一份。无System，用户末尾统一加` /no_think`，助手为`<think>\n\n</think>\n\n`加可见答案（实际文件内为换行，非字面反斜杠）。没有人工思考链，也不混两种模式。沿用现有非思考样式是本轮的明确选择，不能据此证明历史长思考／混合格式没问题。

沿用现有身份损失插件但新样本不命中任何身份key，实际不应有3倍监督；不加载v0.1.26/27的来源置零插件，不加KL。必须先与原生`ignore_empty_think`核对实际编码和损失等价，不能只凭配置名称认定正确。

## 先检查监督，再运行一个候选

执行前需用当前真实Swift环境展示全部16条的Token、labels、loss_scale和最终有效掩码：用户问题不得被监督，可见答案必须有监督；空think、模板边界和EOS实际如何处理逐段列明。检查同输入下现有插件与原生策略的掩码、损失和梯度是否一致，且16条都未被删除或截断。这些目前均为待做项。

拟从Qwen/Qwen3-8B重新初始化LoRA，保留r8、alpha32、dropout0.05、all-linear、lr1e-4、BF16、batch1、累积16、max_length2048、seed/data_seed42。其他Trainer参数执行前从现有环境回读确认。

仅8个优化器步，每步恰好覆盖16条一次，预计每条读取8次、共128次曝光。保存训练前及第1、2、4、8步，生成主要比较第0、2、4、8步。每步记录实际学习率、裁剪前梯度范数、权重变化；在固定eval模式下看16条各自的答案NLL，不只看平均loss。无额外优化器Smoke，无第二次Full。

保留cosine和warmup_ratio=0.05，但8步调度不同于原66步；第一次实际更新的学习率可能为0，必须回读，不能把零学习率下无变化当作正常训练证据。初始LoRA应检查有效增量为0，而非要求随机初始化的A矩阵为0。

**这是一套简单参考实验，不是v0.1.27的单因素因果延续。** 数据长度、模式组成、样本分布、总步数和曝光均有变化。结果回答“这套简单监督下是否复现”，不能直接判定原数据或原配方谁有错。

## 生成检查：最多176次

保留修正后的vLLM模板及当前System原文，测试自然问题，不额外拼`/no_think`；非思考模式，分别不传System和传冻结System。选6道已有问题定位复述、错误润色、事实反转和循环，另选2道保留能力题；题号、原题哈希和判据见protocol。既有8题只作开发诊断，未混入训练。

|环节|模型|题目／条件|请求数|
|---|---|---|---:|
|确定性观察|原版、未训练LoRA、第2/4/8步|8题×2种System，各1次|80|
|采样观察|原版、第8步|8题×2种System，各3次|96|
|合计|||176|

确定性观察用temperature=0、top_p=1、top_k=-1；采样观察沿用temperature=0.7、top_p=0.8、top_k=20。两者max_tokens均为2048，repetition_penalty=1，presence/frequency_penalty=0，min_p=0，n=1，非流式，不传请求seed。不同解码配置分开比较，不能把它们混成一个通过率。

原版在同一协议下重跑，不拿历史随机回答代替确定性基线。零更新LoRA与原版如有差异，先看输入、加载和数值：相近logit的贪婪分叉不等于实现bug。尽量一次加载推理基座，使用保存的LoRA别名，避免每个检查点重新启动服务。

8题均不依赖JSON Schema，不引入输出强制约束掩盖模型行为。格式训练样本中的JSON按普通文本监督。独立记录完全复述、近似复述、循环、任务完成、事实保持、无依据新增、空正文和截断；引用题面后完成任务不算复述。原版已有的错误与新增退化分开。无需外部Judge或并行Agent。

同一题只有3次采样，检出能力有限；不能因0次失败就断言没有退化。所有请求保留原始响应，不因答案差而重试。技术失败也保留计数，不自动扩大请求预算。

## 结果如何决定下一步

|观察|解释与下一步|
|---|---|
|未训练LoRA已经出现实质异常|先排查加载、实际输入、模板和数值，不归因于SFT数据|
|少量有效更新后出现新的可复现失败|优先定位监督位置、梯度／更新幅度；单个失败不足以证明代码bug|
|仅较后检查点变差|考虑重复曝光或累计更新影响，不自动降学习率重跑|
|权重确有变化、拟合有进展，未观察到新退化|只证明这套短非思考监督下未复现，再逐类加入一个来源或格式|
|loss、权重几乎没变化|实验信息不足，不能声称训练链路已排除|

不按这些开发题挑一个“最好检查点”发布，不通过增加轮次或改判据追求通过。此前61次业务／格式监督的证据保留，等简单基线结果出来后再决定加入顺序。
